## Known-Correct API Values

- CatBoost `loss_function` for binary log-loss classification is `'Logloss'` — capital L, no underscore, no other capitals. `'Log_loss'` and `'LogLoss'` will error.
- CatBoostClassifier DOES support a `class_weights` parameter directly (unlike some earlier belief) — pass it as a list ordered by class index: `class_weights=[weight_for_0, weight_for_1]`. Do not substitute `scale_pos_weight` instead — it implements a different formula and will not match a prompt's explicit class_weights specification. If you're unsure whether a parameter exists, check with `CatBoostClassifier().get_params()` or the actual error message rather than assuming a limitation.
- To retrieve per-iteration train/validation metric history from a fitted CatBoost model, use `model.get_evals_result()` — returns `{'learn': {'Logloss': [...]}, 'validation': {'Logloss': [...], 'AUC': [...]}}`. Do not guess at alternative method names (`get_fold_iterations_logloss`, `get_eval_metrics`, `get_fold_iterations_mse`, etc.) — these are not standard CatBoost methods. If unsure of a method name, check `dir(model)` or read the actual error message before retrying with another guess.
- If a library call fails on a parameter's string value, do not guess more than twice. If you can't determine the correct value from the error message, stop and say so explicitly — do not silently substitute a different parameter that changes what was actually asked for (e.g. swapping loss functions changes the comparison being requested, not just the syntax).
- sklearn's fitted `DecisionTreeClassifier.tree_` object has no `n_samples` attribute — the correct attribute for per-node sample counts is `n_node_samples` (e.g. `model.tree_.n_node_samples[leaf_idx]`). `AttributeError: 'sklearn.tree._tree.Tree' object has no attribute 'n_samples'` means this mistake, not a missing installation.

## Reuse the Champion Model, Don't Rebuild It

When a task says "using the champion model from C11" (or similar), do not retrain a fresh model from scratch for each downstream question. Train the exact model once, with its exact configuration (same parameters, same class_weights), save its predictions (e.g. `val_probs`) to a file or variable, and reuse those saved predictions for every subsequent question that references it. Retraining from a vague memory of the original setup risks silently using different weighting or parameters each time, producing inconsistent results across what should be one continuous analysis.

## No Cross-Question Value Reuse

Never reuse a numeric result from a different question in this session without recomputing it fresh for the current question, even if a value seems to fit. If a number you're about to report exactly matches a value already given for a different question or metric, treat that as a strong signal of an error, not a coincidence — stop and recompute independently before submitting it. This applies even when the two questions involve different models (e.g. a Random Forest threshold sweep landing on the exact same threshold and cost as an earlier CatBoost sweep is not plausible and should be re-run).

## Background Process Handling

When an `exec` call spawns a long-running background process (e.g. model training), poll that same process/session ID repeatedly until it completes, rather than abandoning it and launching a new, duplicate run. A single poll with no result is not evidence of failure — wait and re-poll the same ID at least 3-4 times before concluding something is wrong.

Never start a second instance of the same expensive operation (e.g. re-fitting the same model) while a prior instance may still be running. If you're unsure whether a process is still active, check its status explicitly rather than guessing and restarting.
